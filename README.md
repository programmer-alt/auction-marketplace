## Описание

**Global Auction Marketplace** — продуктовая международная платформа для онлайн-аукционов. Это не просто CRUD-приложение: это высоконагруженная система с торгами в реальном времени, безопасными платежами через Stripe, защитой от гонок при одновременных действиях, и комплексной системой безопасности.

Проект демонстрирует продвинутые паттерны разработки:
- **Чистая архитектура** с разделением на Контроллеры → Сервисы → Репозитории
- **Защита от гонок** через транзакции Prisma на уровне базы данных
- **Безопасность на уровне предприятия** с 10+ слоями защиты (CSRF, CSP, ограничение запросов, очистка ввода)
- **Коммуникация в реальном времени** через Socket.io с автоматическим переподключением
- **Метрики Prometheus** для мониторинга производительности
- **Курсорная пагинация** для навигации O(1) по большим наборам данных

## Ключевые особенности

### 🚀 Защита от гонок при ставках (Race Condition)

Каждая ставка обрабатывается через **атомарную транзакцию Prisma**, которая одновременно:
1. Проверяет, что аукцион активен и время не вышло
2. Проверяет, что ставка выше текущей
3. Проверяет, что пользователь не продавец
4. Обновляет текущую цену и идентификатор победителя
5. Создаёт запись ставки

Всё это — **в одной транзакции на уровне базы данных**, что полностью исключает гонку при одновременных ставках.

### 🔐 Безопасность на уровне предприятия (10+ слоёв защиты)

| Слой | Технология | Что защищает |
|------|-----------|-------------|
| **CSRF** | Double-submit cookie + криптографическая подпись | CSRF-атаки на все POST/PUT/DELETE |
| **CSP** | Кастомный middleware с 15+ директивами | XSS, clickjacking, frame injection |
| **Ограничение запросов** | LRU-кэш + нормализация IP (IPv4/IPv6) | DDoS, перебор паролей, злоупотребление API |
| **JWT** | Access + Refresh token + tokenVersion | Утечка токенов, сессии |
| **Очистка ввода** | Рекурсивная очистка всех строковых полей | XSS через пользовательский ввод |
| **HPP** | Helmet + HPP middleware | Загрязнение HTTP-параметров |
| **HSTS** | Strict-Transport-Security (1 год) | Перехват SSL |
| **Permissions-Policy** | camera=(), microphone=(), payment=() | Ограничение доступа к API браузера |

### 💳 Интеграция Stripe с ручным списанием (Manual Capture)

Уникальный процесс оплаты, который **замораживает** средства победителя и проигравших:
1. **При ставке** — создаётся PaymentIntent с `payment_method_types: card`
2. **При выигрыше** — статус `AUTHORIZED` (средства заморожены, но не списаны)
3. **При завершении аукциона** — автоматическое списание `capture()` для победителя
4. **Для проигравших** — автоматическая отмена `cancel()` заморозок

Поддержка **150+ валют**, включая валюты без дробной части (JPY, KRW, VND, CLP...).

### 🔄 Система реального времени WebSocket

Сервер Socket.io с:
- **Рассылка по комнатам** — только подписчики получают обновления
- **Middleware авторизации** — проверка JWT при подключении, поддержка гостей
- **Ограничение подключений** — защита от перегрузки WebSocket
- **Автоматическое переподключение** — экспоненциальная задержка с 5 попытками
- **События**: уведомления о создании аукционов, новых ставках, обновлениях, завершении и удалении

### 📊 Мониторинг Prometheus

Метрики для Grafana/Prometheus:
- **HTTP**: гистограмма времени ответа, счётчик запросов
- **База данных**: время запросов + количество по операциям и таблицам
- **WebSocket**: текущие соединения, количество сообщений по событиям
- **Бизнес-метрики**: созданные аукционы, ставки, обработанные платежи

Система готова для прямого сбора метрик Prometheus.

### ⚡ Курсорная пагинация (Cursor-Based)

Более эффективная чем offset/limit:
- **O(1) навигация** — не зависит от объёма данных
- **Составные курсоры** — поддержка нескольких полей сортировки
- **Двусторонняя** — навигация "вперёд" и "назад"
- **Кодировка Base64** — безопасная сериализация курсоров

### 🔄 Автоматическое переподключение к базе данных

Умное переподключение с **экспоненциальной задержкой** для работы с пулами соединений:
- Автоматическое восстановление при обрывах соединений
- Объединение одновременных попыток переподключения (только одна активная)
- Middleware повторов для временных ошибок соединения

### 🧹 Система очистки ввода (Sanitization)

Рекурсивная очистка всех пользовательских данных:
- **Защита от XSS**: удаление опасных тегов и скриптов
- **Очистка URL**: блокировка опасных протоколов
- **Очистка HTML**: whitelist разрешённых тегов
- **Валидация email**: проверка формата + приведение к нижнему регистру + удаление пробелов
- **Очистка чисел**: обнаружение некорректных значений + проверка типов

### 🛠 Корректное завершение работы (Graceful Shutdown)

Обработка системных сигналов завершения (включая Windows Ctrl+C):
- Закрытие HTTP сервера (новые запросы не принимаются)
- Очистка всех таймеров и интервалов
- Отключение connection pool Prisma
- Принудительный выход через 10 секунд (защита от зависания)
- Защита от повторного запуска через внутренний флаг

### 🕐 Фоновая задача (Cron Job)

Автоматическое завершение истёкших аукционов каждые **5 минут**:
- Поиск активных аукционов, время которых истёк и есть победитель
- Автоматическое списание платежа победителя
- Автоматическая отмена заморозок проигравших
- WebSocket уведомление подписчиков

### 🧪 Тестовое покрытие

**18 тестовых файлов** покрывают ключевые компоненты:
- Контроллеры и сервисы (auctions, auth, bids, payments)
- Middleware (auth, CSRF, rate limiting, admin)
- Репозитории (users, payments, auctions, bids)
- Обработка ошибок и фабрики ошибок

Фреймворк: **Vitest** + **Supertest** + **@vitest/coverage-v8**

## Безопасность

### Защита от OWASP Top 10

| Уязвимость | Решение |
|-----------|---------|
| **A02: Провалы криптографии** | Хеширование паролей + криптографические токены CSRF + подписание JWT |
| **A03: Инъекции** | ORM с параметризованными запросами + очистка ввода |
| **A07: Ошибки идентификации и авторизации** | Токены авторизации + ограничение запросов + инвалидация сессий |
| **A09: Логирование и мониторинг** | Структурированное логирование + метрики + обработка ошибок |

### Заголовки безопасности (каждый HTTP-ответ)

Сервер устанавливает заголовки для защиты от XSS, clickjacking и других атак: Content-Security-Policy, защита от просмотра в фрейме, запрет на анализ типов контента, политика реферера, ограничения на использование API браузера, строгая транспортная безопасность.

### Защита CSRF

Шаблон double-submit cookie с криптографической подписью:
1. Сервер генерирует криптографический уникальный токен
2. Вычисляется хеш-сумма секретного ключа и токена
3. Подписанный токен хранится в безопасной httpOnly cookie
4. Клиент отправляет тот же токен в заголовке запроса
5. Сервер проверяет подпись за постоянное время (постоянное время выполнения)

### Ограничение запросов (Rate Limiting)

- **Кэш в памяти**: хранение записей с автоматической очисткой
- **Нормализация IP**: приведение IPv6-форматов к IPv4, обработка локальных адресов
- **Учёт прокси**: учёт заголовков клиента для работы через Docker/K8s
- **Доверенные подсети**: частные сети исключены из подсчёта
- **Настраиваемый**: разные лимиты для production и development

## Мониторинг и производительность

### Метрики Prometheus

Система собирает метрики для мониторинга в Grafana/Prometheus:
- **HTTP-запросы**: время ответа и общее количество с разбивкой по методу, маршруту и коду ответа
- **База данных**: время запросов и количество операций по типам и таблицам
- **WebSocket**: текущие соединения и количество сообщений
- **Бизнес-метрики**: созданные аукционы, сделанные ставки, обработанные платежи

Данные метрики доступны для прямого сбора инструментами Prometheus.

### Управление ресурсами

- **Обнаружение утечек памяти**: периодическая проверка каждые 10 минут
- **Настройки среды выполнения**: управление сборщиком мусора для стабильной работы
- **Корректное завершение**: обработка системных сигналов с принудительным выходом через 10 секунд
- **Connection pool**: оптимизирован для работы через прокси-пулы соединений

## Установка

1.  Клонируйте репозиторий:

    ```bash
    git clone https://github.com/your-username/global-auction-marketplace.git
    cd global-auction-marketplace
    ```

2.  Установите зависимости для фронтенда и бэкенда:

    ```bash
    npm run install:all
    ```

3.  Настройте переменные окружения (скопируйте `.env.example` в `.env` и заполните значения).

4.  Запустите приложение в режиме разработки:
    ```bash
    npm run dev
    ```

## Как это работает

### Процесс ставки (без гонки)

```
Пользователь нажимает "Сделать ставку"
  │
  ├─ Фронтенд: проверяет валидность суммы ставки
  │
  ├─ API: POST /api/auctions/:id/bids { amount }
  │
  ├─ Middleware: авторизация → проверка CSRF → ограничение запросов
  │
  └─ Сервис: bids.service.createBid()
       │
       ├─ 1. Загрузка данных аукциона из БД
       │
       ├─ 2. Ранняя проверка (время не вышло, валюта совпадает)
       │
       └─ 3. prisma.$transaction([
            ├─ auctions.update({
            │    where: { id, статус активен, время не вышло, сумма валидна, пользователь не продавец },
            │    data: { обновлённая цена, идентификатор победителя }
            │  })
            │
            └─ bids.create({ auctionId, userId, amount })
          ])
          │
          ├─ ✅ Успех → WebSocket рассылка уведомления о ставке
          └─ ❌ Ошибка → "Аукцион не найден, не активен, завершён или ставка слишком низкая"
```

### Процесс платежей (ручное списание)

```
1. Пользователь делает ставку
   └─ PaymentIntent создан (статус: PENDING)

2. Stripe подтверждает платёж
   └─ Webhook: payment_intent.requires_capture
   └─ Статус платежа → AUTHORIZED (средства заморожены, но не списаны)

3. Аукцион завершён → определён победитель
   └─ Автоматическое завершение (каждые 5 минут)
   └─ capturePayment(winnerPaymentId) → статус COMPLETED
   └─ cancelHold(otherPayments) → статус удалён (средства возвращены)

4. Если аукцион отменён / нет победителя
   └─ cancelHold(allPayments) → средства автоматически возвращаются
```
