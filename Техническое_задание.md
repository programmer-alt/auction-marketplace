# Техническое задание: Auction Marketplace

**Проект:** Auction Marketplace  
**Роль:** Full-Stack Developer  
**Дата:** Март 2026

---

## 1. Цель проекта

Создать платформу для проведения аукционов с возможностью:

- Размещения лотов продавцами
- Размещения ставок покупателями
- Оплаты через Stripe
- Просмотра истории транзакций
- Real-time обновления ставок через WebSocket
- Автоматического завершения аукционов по времени
- Защиты от злоупотреблений (rate limiting, CSRF, валидация)

## 3. Структура базы данных (Prisma Schema)

```prisma
model User {
  id        Int       @id @default(autoincrement())
  email     String    @unique
  password  String
  name      String?
  balance   Decimal   @default(0) @db.Decimal(10, 2)
  auctions  Auction[] @relation("SellerAuctions")
  bids      Bid[]
  payments  Payment[]
  createdAt DateTime  @default(now())
}

model Auction {
  id           Int        @id @default(autoincrement())
  title        String
  description  String?
  imageUrl     String?
  startingPrice Decimal    @db.Decimal(10, 2)
  currentPrice Decimal    @db.Decimal(10, 2)
  sellerId     Int
  seller       User       @relation("SellerAuctions", fields: [sellerId], references: [id])
  winnerId     Int?
  winner       User?      @relation("WinnerAuctions", fields: [winnerId], references: [id])
  status       AuctionStatus @default(ACTIVE)
  endsAt       DateTime
  bids         Bid[]
  payments     Payment[]
  createdAt    DateTime   @default(now())
}

model Bid {
  id        Int      @id @default(autoincrement())
  auctionId Int
  auction   Auction  @relation(fields: [auctionId], references: [id])
  userId    Int
  user      User     @relation(fields: [userId], references: [id])
  amount    Decimal  @db.Decimal(10, 2)
  createdAt DateTime @default(now())
}

model Payment {
  id              Int            @id @default(autoincrement())
  userId          Int
  user            User           @relation(fields: [userId], references: [id])
  auctionId       Int
  auction         Auction        @relation(fields: [auctionId], references: [id])
  amount          Decimal        @db.Decimal(10, 2)
  stripePaymentId String?
  status          PaymentStatus  @default(PENDING)
  createdAt       DateTime       @default(now())
}

enum AuctionStatus {
  ACTIVE
  COMPLETED
  CANCELLED
}

enum PaymentStatus {
  PENDING
  COMPLETED
  FAILED
}
```

## 4. API Endpoints

### Аутентификация

- `POST /api/auth/register` - Регистрация (с rate limiting)
- `POST /api/auth/login` - Вход (с rate limiting)
- `GET /api/auth/me` - Текущий пользователь (обязательная аутентификация)

### Аукционы

- `GET /api/auctions` - Список аукционов (опциональная аутентификация)
- `GET /api/auctions/:id` - Детали аукциона (опциональная аутентификация)
- `POST /api/auctions` - Создать аукцион (только продавец, обязательная аутентификация)
- `PUT /api/auctions/:id` - Обновить аукцион (только продавец)
- `DELETE /api/auctions/:id` - Удалить аукцион (только продавец)

### Ставки

- `POST /api/auctions/:auctionId/bids` - Сделать ставку (обязательная аутентификация)
- `GET /api/auctions/:auctionId/bids` - История ставок (публичный доступ)

### Платежи

- `POST /api/payments/create-intent` - Создать Payment Intent (обязательная аутентификация)
- `POST /api/payments/webhook` - Webhook Stripe (публичный, без аутентификации)
- `GET /api/payments/history` - История платежей (обязательная аутентификация)

## 5. Архитектура и middleware

### Безопасность

1. **Helmet** — устанавливает security HTTP-заголовки.
2. **HPP** — защита от параметрического загрязнения.
3. **CORS** — настройка кросс-доменных запросов.
4. **CSRF защита** — middleware для защиты от CSRF-атак на state-changing запросы.
5. **Rate Limiting**:
   - Глобальный лимит: 100 запросов в минуту на IP (с использованием Redis, fallback на in-memory store при недоступности Redis).
   - Лимиты на аутентификацию: 5 попыток входа и 10 регистраций за 15 минут с одного IP.
6. **Аутентификация**:
   - JWT токены, передаваемые в заголовке `Authorization: Bearer <token>`.
   - Обязательная аутентификация (`authMiddleware`) для защищённых маршрутов.
   - Опциональная аутентификация (`optionalAuthMiddleware`) для маршрутов, где пользователь может быть неавторизован, но если токен предоставлен — он валидируется.
7. **Валидация**:
   - Все входящие данные валидируются с помощью Zod на стороне бэкенда.
   - Формы на фронтенде также используют Zod для предварительной валидации.

### Real-time коммуникация

- **Socket.io** с Redis адаптером для горизонтального масштабирования.
- События:
  - `bid:created` — новая ставка на аукционе.
  - `auction:updated` — обновление данных аукциона.
  - `auction:completed` — завершение аукциона.

### Фоновые задачи

- **Bull** — очередь задач на основе Redis.
- Задачи:
  - Завершение аукциона по истечении времени `endsAt`.
  - Отправка уведомлений победителю и продавцу.

### Кэширование

- Redis используется для кэширования:
  - Списки аукционов (TTL 60 секунд).
  - Отдельные аукционы (TTL 60 секунд).
- Инвалидация кэша при изменении данных.

### Тестирование

- **Vitest** — unit и интеграционные тесты.
- **Supertest** — HTTP тестирование эндпоинтов.
- Тестовое окружение использует отдельную базу данных и Redis.

## 6. Основные функции

1. **Регистрация/Вход** — JWT токены, хеширование паролей bcrypt.
2. **Создание лота** — форма с валидацией, загрузка изображений (URL), установка времени окончания.
3. **Просмотр лотов** — пагинация, фильтрация по статусу, поиск, сортировка.
4. **Размещение ставок** — real-time обновление через WebSocket, проверка на превышение текущей цены.
5. **Завершение аукциона** — автоматически по времени через очередь задач, определение победителя.
6. **Оплата** — интеграция Stripe Checkout, создание Payment Intent, обработка вебхуков.
7. **История** — личный кабинет: мои аукционы, мои ставки, платежи.
8. **Таймер аукциона** — обратный отсчёт на странице аукциона с возможностью паузы/возобновления (демо-режим).
9. **Защита от злоупотреблений** — rate limiting, CSRF, валидация, безопасные заголовки.

## 8. Почему эти технологии?

### Prisma

- Type-safe запросы к БД
- Автоматические миграции
- Простая схема данных
- Отличная документация

### Tailwind CSS

- Быстрая стилизация
- Не нужно писать CSS файлы
- Современный вид "из коробки"

### Zod

- Валидация на фронтенде и бэкенде
- TypeScript совместимость
- Понятные ошибки

### Socket.io

- Real-time ставки
- Уведомления о новых ставках
- Простой API

### Redis

- Кэширование для повышения производительности
- Адаптер для Socket.io для горизонтального масштабирования
- Очереди задач (Bull) для фоновых операций
- Rate limiting с отказоустойчивостью

### Vitest

- Быстрые unit-тесты
- Совместимость с ES модулями
- Интеграция с TypeScript

## 9. Деплой и инфраструктура

- **Backend**: развертывание на платформе (например, Railway, Render, или собственный сервер) с поддержкой Node.js.
- **Frontend**: хостинг на Vercel (оптимизирован для Next.js) или аналоги.
- **База данных**: управляемый PostgreSQL (например, Supabase, AWS RDS).
- **Redis**: облачный Redis (Upstash, Redis Cloud) или контейнеризованный.
- **Мониторинг**: логгирование ошибок (Sentry), метрики (Prometheus/Grafana) — опционально.
- **CI/CD**: GitHub Actions для автоматического тестирования и деплоя.
